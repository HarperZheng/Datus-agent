> 定位：给指挥方（Claude Code 会话）看的任务书。业务口径见 00-06 各文件，本文只定与执行路径无关的指挥层不变量。
> 维护方式：手工维护（非 xlsx 导出）；环境或验收标准变化时手动更新。
> 职责分工：业务口径与红线由本文定死；口径 → Dosi 结构的翻译由 `semantic_modeling` 子代理按其能力目录自定；指挥方负责派活、验收、守红线。

## 二、终态验收单（DoD）

建模完成的判定标准，与执行路径无关：

1. **模型文件**：subject/semantic_models/fujian1105/ 下一个模型 yml，内含
   - 3 个 dataset：收缴清分、专户代收收入、国库收入（dataset 与指标命名由子代理定）
   - 数据集一 ↔ 数据集三的三键对齐 relationship
   - 05-预设指标清单 20 条全量：#1-6 基础、#7-10 同比、#11-20 状态快照
2. **校验**：`validate_semantic` 结构校验通过，模型已同步 Knowledge Base
3. **反向核对（红线 4 的机械执行）**：Claude Code 读回 yml，逐列核对——出现的每个物理列名必须命中 01-03 白名单；命中黑名单（06）或白名单之外的列名视为失败，删除该次产出并重新下发请求。纯字符串比对，不依赖判断
4. **数值对照降级策略**：ClickHouse 23.3 Bug 2（query_metrics 报 Code 115 UNKNOWN_SETTING session_timezone）修复前，指标执行校验必然失败——记 unverified/failed 并注明原因，不算建模失败，不反复重试；Bug 修复后要求 `verify_semantic_outputs` 通过。`validate_semantic` 与普通 SQL 问答不受 Bug 2 影响
5. **结果核验通道**：CLI 返回状态（generated / skipped / blocked）+ 读回 yml 文件核对。blocked 表示目标模型缺失或无效，需检查请求后重发

## 三、硬约束红线（写进每条建模请求）

1. **五要素同表**（00·指标规则1）：度量、行集条件、固化取值、时间锚、分组维度必须落在同一数据集；任一要素跨数据集的需求不单设指标
2. **粒度与去重**（00·规则2）：指标 #1 SUM(ftotalamt) 按 fpaycode 去重、#2/#4 SUM(famt) 按 (fpaycode, fid) 去重，去重键必须落实；fimamt（清分明细粒度）与 famt（缴库拆分行粒度）不得混加
3. **时间锚即口径**（00·规则3）：每条指标绑定 05 清单指定的时间锚字段，不得换锚、不得默认换锚
4. **字段白名单**：只建模 01-03 白名单列出的字段；describe_table 看到的其他字段一律不写入模型，即使看似有用；确有扩展需求停下回报，不自行决定
5. **同名陷阱**：缴库宽表 ftotalamt、fdate 均为黑名单（06），数据集三建模时不得带入；数据集三的时间字段只有 fpaydate / ftransdate / fenterdate
6. **三集同一模型文件**：semantic_modeling 每次只编辑一个语义模型，全部 dataset、relationship、metric 落入同一个 yml
7. **对齐关系**：数据集二 ⊂ 数据集一为行级子集（同源同键，行键 (fpaycode, fid, fcollectid) 相等），不建 JOIN relationship；数据集一 ↔ 数据集三按三键对齐声明，关联查询时金额一律用收缴清分侧 fimamt（00·规则4）
8. **口径以 05 原文为准**：固化谓词、近义词、双答制（「已收缴」→ #4+#12 并列返回、不加总）按 05 清单原文执行，不得增删改

## 四、任务拆解与批次原则（Claude Code 预设，非固定剧本）

- **依赖顺序**：datasets → relationship → 基础指标（#1-6, #11-20）→ 同比（#7-10）
- **批次大小现场自定**：可一次全量下发，也可按 dataset / 指标组分批；判据是失败可定位、重试代价小
- **失败重试粒度**：单 dataset / 单指标，不整批重来；同一请求连续失败两次后停下报告，不无限重试
- **请求写法**：每条请求指向材料文件 + 条目号（如「05-预设指标清单.md #4」），口径原文让子代理 read_file 自取，不在请求里转述口径（转述会引入抄写错误）

## 五、职责边界（指挥方不做什么）

以下全部由 `semantic_modeling` 子代理按请求口径与其能力目录自行决定，指挥方不预设、不检查「翻译方式是否与预想一致」，只按第二部分验收单对结果：

- SQL dataset / 物理 dataset 的选择与行段 SQL 写法
- 固化谓词的表达方式（derive 过滤指标、CASE WHEN 等）
- 同比指标的 window 配置
- 指标与 dataset 的命名（slug 语言与风格）
- 近义词、双答制在 description / ai_context 中的落点
- Relationship 的方向、列序与 join_type
